Deadline callbacks now receive a runtime-built Airflow context (``dag_run``, ``run_id``, ``logical_date``, ``ds``, ``ts``, ``deadline``, etc.) and their string kwargs are rendered with Jinja using that context, on both the triggerer and executor paths. The ``dag_run`` entry in that context now uses the same shape the Task SDK gives tasks, so a callback that read fields off the previous scheduler-built context may need updating. Deadline Alerts are still experimental.
